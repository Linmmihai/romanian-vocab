# 罗马尼亚语词汇学习应用

[English README](README.md)

这是一个面向中文使用者的罗马尼亚语学习应用。应用结合了词汇卡片、间隔复习、测验、完整语法目录、学习统计和 Android APK 打包功能。

界面目前主要使用中文，因为目标用户是从中文学习罗马尼亚语。

## 主要功能

- **每日任务队列**：默认每天处理 200 个词，先完成正式到期复习/重新学习，再处理到点的初次学习步骤，最后用剩余空位学习未学词；当天固定队列不会因为延迟重试而扩充到第 201 个。
- **分层词书**：默认学习 1,789 条新闻通用核心；新闻扩展、生活场景和十类专项术语按需切换，切换时保留原学习进度。
- **卡片记忆**：点击或滑动卡片查看罗马尼亚语、明确标注的重音、规范化语法，以及彼此独立的主题、词性和词汇单位。
- **间隔复习**：学过的词会按复习阶段安排下一次复习，例如 20 分钟、1 天、2 天、4 天等。
- **记忆追踪**：记录词条是否看过、是否认识、答题次数、复习阶段、下次复习时间、需加强次数、连续错误和最近错误时间。
- **测验模式**：支持中罗互译，以及名词复数、动词类型、重音等专项练习。
- **语法知识库**：按词法、句法和语用等八个语法模块整理专题，支持搜索和展开阅读结论、核心规则及双语例句；动词专题提供词缀或构成表，有配套课程时可直接前往 Bilibili。
- **学习统计**：显示每日学习量、连续学习天数、正确率、主题掌握率和高频错词。
- **词汇表**：支持按中文、罗语、主题或词性搜索，并可分别筛选主题与词性。
- **离线模式**：可使用内置本地词库，并把学习进度保存在本机。
- **管理员功能**：管理员可以用结构化字段添加、编辑和审核词条；质量门会检查模板内容、规范化重复、主题/词性缺失、语法矛盾、重音和双语例句完整性。
- **Android APK 打包**：通过 Capacitor 将网页应用打包成 Android 应用。

## 技术栈

- 原生 HTML、CSS、JavaScript
- Supabase：用户登录、共享数据和学习进度存储
- Capacitor Android：Android APK 打包
- esbuild：打包 Supabase 浏览器依赖
- `data/vocab.json`：本地词库文件

## 本地运行

安装依赖：

```bash
npm ci --prefix "app build"
```

构建网页文件：

```bash
npm --prefix "app build" run build:web
```

建议通过本地服务器打开 `app build/www`，不要直接用 `file://` 打开 `index.html`。例如：

```bash
npx http-server "app build/www" -p 4173 -c-1
```

然后访问：

```text
http://127.0.0.1:4173/
```

直接用 `file://` 打开可以用于快速查看界面，但登录和同步行为可能不稳定。

## 构建 Android APK

先构建网页并同步到 Android：

```bash
npm --prefix "app build" run cap:sync
```

构建调试版 APK：

```bash
npm --prefix "app build" run apk:debug
```

生成的 APK 通常位于：

```text
app build/android/app/build/outputs/apk/debug/app-debug.apk
```

如果手机已开启 USB 调试并连接电脑，可以安装：

```bash
adb install -r "app build/android/app/build/outputs/apk/debug/app-debug.apk"
```

如果要发布正式版本，请先修改：

```text
app build/android/app/build.gradle
```

中的：

```gradle
versionCode
versionName
```

## Supabase 说明

应用在 `api.js` 中使用 Supabase anon key。对浏览器客户端来说这是正常做法，但数据库安全依赖 Supabase 的 Row Level Security 策略。

每日状态同步依赖 `tools/atomic_daily_state_sync.sql`。部署网页或 APK 的
`20260804-atomic-daily-sync-v5` 版本之前，必须先在目标 Supabase 项目执行该迁移。
迁移会增加幂等事件表、客户端序列头和 `apply_daily_state_sync_event` 原子 RPC；
未安装迁移时，新客户端只保留本机待同步事件，不会退回不安全的整行覆盖写入。

需要确保：

- 普通用户只能读写自己的学习进度和个人资料。
- 管理员操作只能由管理员执行。
- 词库、报错、用户管理等表有正确的权限限制。
- `daily_queue` 与 `daily_log` 只能通过原子事件 RPC 合并；客户端不能直接 upsert 每日快照。

应用也支持离线模式。离线模式下，学习进度保存在浏览器或 Android WebView 的本地存储中。

## 记忆系统概览

每个词都有一份学习进度状态。主要字段包括：

- `seen`：用户已经接触过这个词。
- `known`：用户曾经标记认识或答对过这个词。
- `qr` / `qt`：答对次数 / 总答题次数。
- `reviewStage`：间隔复习阶段。
- `nextReviewAt`：下一次应复习时间。
- `wrongCount`：累计答错次数和复习优先级证据。
- `errorStreak`：当前连续错误次数。
- `lastWrongAt`：最近一次答错时间。

每日任务队列按阶段严格出卡：正式到期复习及其重新学习步骤优先，其次是初次学习中已到点的步骤，最后才是真正未学过的新词。只要前两个阶段仍有到期卡片，新词就不会穿插出现。默认每日通过目标为 200，同时另设每日新词上限 30；新词上限只控制第一次引入的卡片，不会阻止已经开始学习的卡片按时重试。新词答错只会留在“学习中”并按短间隔重试；已经毕业进入复习阶段的词再次答错，会进入重新学习并继续作为正式复习优先处理。

每日通过目标按“准确回忆”的卡片数计算。例如目标为 30、当前有 200 个到期复习时，完成 30 个就已达标；之后可以结束、再完成 10 个、自定义数量，或选择清空剩余复习。新词上限与临时复习加量保持独立，而且只有正式复习清空后才会开始新词。当前卡片必须翻面并选择记忆结果，方向键或滑动不会跳过未作答单词。

## 状态逻辑手动检查

修改打卡、每日任务或复习逻辑后，至少检查这些路径：

- 新词点“不认识”：今日完成数不增加，刷新后仍不计入完成，保持“学习中”，并按短间隔等待学习步骤；不能被当作已经毕业后的遗忘。
- 新词点“认识了”：今日完成数只增加一次，刷新后仍保留，词从今日开放队列移除。
- 每日通过目标和每日新词上限独立：默认可通过 200 个，但最多只首次引入 30 个新词；未点“准确回忆”的词不会被第 31 个新词替换。
- 卡片不能跳过：右方向键或左滑只会提示完成当前卡片；作答后系统才自动进入下一词。
- 达标后续量：可到此结束、再完成 10 个、自定义数量或清空剩余正式复习；临时加量不会提高新词上限。
- 学习与复习分流：初次学习中的到期步骤保持“学习中”，不会计入“正式待复习”或“到期复习”模式；有正式复习时，它们也不会抢占通过目标。
- 达到固定目标：弹出打卡窗口；未点打卡前，日历和连续天数不应显示今天已完成。
- 同一天重复打卡或刷新后再点打卡：今天只保持一个完成状态，弹窗不应重复出现。
- 出卡顺序：正式到期复习/重新学习 → 已到点的初次学习步骤 → 新词；任何前序队列未清空时都不能提前显示后序卡。
- 回看与撤销：回看上一张时不能再次评分；撤销会恢复词条进度、今日队列、通过计数、新词计数和待同步状态。
- 复习队列：答错已毕业/已掌握词后进入重新学习，按短间隔优先复习，并继续保留历史掌握证据。

## 开发说明

- `app build/www/` 和 `app build/android/app/build/` 是构建产物，可以重新生成。
- 核心模块职责和修改边界见 `ARCHITECTURE.md`。
- 提交代码前运行完整校验：

```bash
node tools/run_checks.js
npm --prefix "app build" run build:web
npm --prefix "app build" run test:e2e
```

- 如果之后还要继续更新 APK，请保留整个项目文件夹，尤其是根目录源码和 `app build/android/` 目录。
- 修改网页代码后，运行：

```bash
npm --prefix "app build" run build:web
```

- 修改后要重新生成 APK，运行：

```bash
npm --prefix "app build" run apk:debug
```
